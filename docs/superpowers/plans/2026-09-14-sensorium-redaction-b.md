# Secrets redaction, PR B — captured values, the content rule, Rust wire v4, the renderers, E16 part B: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every captured value a recorder stores — a CALL argument, a LINE delta, a RETURN value, a map value under a secret-named key, an output chunk, an exception message — is redacted by rule v1 at the writer: whole and keyed-digested when its NAME fires, span-replaced when its CONTENT matches; every reader renders the marker and never the value; `watch` and `flow` say what they cannot compare; the trace counts what it withheld — measured once as E16 part B.

**Architecture:** One content-rule module per language beside PR A's name-rule module (`src/sensorium/redact_content.py`, `rust/cargo-sensorium/src/convert/redact_content.rs`, the `content` half of `typescript/src/redact.mjs`), all three pinned to the fixture's `content` list. In Python every redaction of a capture goes through ONE module, `src/sensorium/redact_values.py`, called by the tracer at its three capture sites, by the output tee and by the TypeScript ingest for spools older than this rule; `record/capture.py` stays a pure capture. The Rust runtime redacts LINE deltas by name on the wire (v4, tag 4) and the converter does the RETURN name rule, the content rule and the exception messages; the TypeScript runtime does names and content in-process and its ingest passes the `redacted` object through. The query side reads one optional key, `redacted`, in `fmt_value`, `expr.resolve`, `flow_values.matches` and `flow_cmd.resolve_object`. The retrofit is PR C's.

**Tech Stack:** Python 3.13 (`src/sensorium/`), pytest; Rust 1.96 (`rust/`, `sensorium-rt` dependency-free, `cargo-sensorium` gains the `regex` crate — cached on this box at 1.13.1); Node ≥ 24 ESM `.mjs` under `typescript/`, `node --test`; the vector runner (`tests/test_vectors.py`); the acceptance-instrument pattern of `tests/acceptance_e16/e16a.*` (part A's, untouched — part B gets its own files beside them).

**Spec:** `docs/superpowers/specs/2026-09-13-sensorium-secrets-redaction-design.md` (on `main` since PR #40, with §13's PR-A amendments). The spec is the authority; this plan is its argument for PR B. Section numbers below (§n) are the spec's unless prefixed by a file name. Plan A (`docs/superpowers/plans/2026-09-13-sensorium-redaction-a.md`) is the precedent for every convention not restated here.

## Decisions this plan makes (each amends the spec non-silently; Task 12 appends them to §13)

| # | decision | why |
|---|---|---|
| B1 | **Wire v4's REDACTED-BY-NAME tag is `4`, not §5.2's `3`.** On a LINE row tag 3 has meant UNBOUND since wire v3 (design 2026-09-12 R3, shipped 0.13.0); §5.2 was written a day later without reading `line.rs`. Tag 4: `u8 truncated` is 0, the text is the 16-hex digest or empty when unkeyed, LINE rows only. A v2/v3 spool's reader keeps refusing tag 4 as `not 0..=3`; a v4 reader refuses `5+` as `not 0..=4`. | the spec's number would have overwritten a shipped meaning |
| B2 | **`by` on a Rust or TypeScript trace:** `recorder` when the header/BOOT carries `redaction` with `mode: on` AND the wire is the value-redacting one (Rust v4; a `sensorium-ts` ≥ 0.6.0 BOOT); `converter` when the converter applied a half the runtime should have (an older wire or BOOT, or a header with no `redaction`). The converter's content-and-RETURN half on a v4 spool is by design (§5.2) and is documented, not a change of hand. | `by` names the last hand that applied the rule; a runtime that did its half is that hand |
| B3 | **`redaction.values` is counted by the trace's WRITER:** the Python recorder at finalize (`redact_values.stats`), the two converters as they build. One per capture redacted by either operation, per output chunk with a content hit, per exception message with a content hit, per map value redacted under a firing key. Absent when `mode: off`. | the count is a witness; only the hand that wrote the trace can witness it |
| B4 | **The per-kind whole-redaction rule** (`redact_values.named`): `str` → `v = "<redacted>"`, `trunc` dropped, digest over the clipped `v`; `num` → `v = "<redacted>"`, digest over `repr(v)`; `obj` → `repr = "<redacted>"`, `trunc` dropped, digest over the clipped `repr`; `dbg` → `v = "<redacted>"`, `trunc` false, digest over `v`; `seq`/`map` → `sample`, `trunc` and `unread` dropped, `type`/`len`/`oid` kept, `digest: null`; `none`, `bool`, `unread` untouched. Every redacted capture carries `"redacted": {"by": "name", "digest": <16 hex>|null}`. | §4.2 spoke of `v`/`repr` only; a container has no stored text to digest and a truth value or `None` withholds nothing |
| B5 | **The content rule reaches every text a recorder stores:** `str` values and `obj` reprs (recursively through `seq`/`map` samples), exception messages (`exc.msg`, a hit adds `redacted` on the `exc` object), and output chunks (the tee, one `write()` at a time — a token split across two writes is not seen; documented). A content hit adds `"redacted": {"by": "content", "digest": null}` and never touches a capture already redacted by name. | §2.3's span operation, stated at every text the format holds |
| B6 | **Redaction state in Python is one module-level `State`** in `redact_values` (`install(key, knobs)` from `boot.run_target` after the key loads; the never-installed default is rule ON and unkeyed), so in-process recordings and the TypeScript ingest see the rule without a key. `record/capture.py` is not changed. | one place; a pure capture stays pure |
| B7 | **The RETURN name rule reads the callee's LAST qualname segment** (`Cls.get_api_key` → `get_api_key` → fires; `<lambda>`, `<module>`, `<genexpr>`, `<anonymous>` never fire — their segments are words in no set). Python: the tracer's `qual`; TypeScript: the frame's code name, kept on the frame from `file()`'s `codes` at `call()`; Rust: the converter's `top.qualname`. | the name a value is returned from is the name it was asked for by |
| B8 | **A `map` sample pair whose KEY is a `str` capture that fires** has its VALUE capture redacted by B4's rule under that key's name. Python only — Rust and TypeScript captures are text, and the content rule is their only reach into a struct's `Debug`/`inspect` rendering (documented). | §4.2's containers sentence |
| B9 | **Converters re-apply idempotently, values included:** the content rule always runs in both converters (a marker or a replaced text is a fixed point — the fixture pins `<redacted>` and `postgres://u:<redacted>@h/db` as no-ops); the CALL/LINE name rule runs in a converter ONLY for a spool whose runtime did not (Rust wire < 4; TypeScript BOOT with no `redaction` or a `version` below 0.6.0) and never on a capture that already carries `redacted`; the RETURN name rule runs in the Rust converter always (the runtime has no qualname) and in the TypeScript ingest only for older BOOTs. | re-digesting a marker would break the equality identity §2.3 keeps |
| B10 | **`watch`:** `expr.resolve` returns a new marker `REDACTED` for a capture with `redacted.by == "name"` (a content-hit text resolves as its stored text — it IS text); `_name`/`_member`/`_length` raise `NotCaptured(name, REDACTED_REASON)` with `REDACTED_REASON = "redacted by rule v1; no comparable value"`; `_render` prints `<redacted; no comparable value>`; the site lands in `unavailable`, so a predicate that meets only redacted values ends in the existing `NOTHING WAS CHECKED`, exit 3. | §6.3 through the sentinel machinery that already exists |
