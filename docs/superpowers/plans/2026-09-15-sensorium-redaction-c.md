# Secrets redaction, PR C — `sensorium redact`, the retrofit of every trace already on disk, E16 part C (H4): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sensorium redact <run> | --all [--dry-run]` applies rule v1 in full to traces already in the store — the environment by NAME, every captured value, output row, exception message and child command line by the writers' own rules — recomputes `env_hash` under the trace's own language formula, stamps `redaction` with `by: "retrofit"`, tightens the file to 0600, and does it through a copy so a killed run leaves the original whole; measured once by E16's H4 on a copy of this box's 273-trace store.

**Architecture:** One judgement module (`src/sensorium/redact_store.py`: `plan()` reads a trace and decides every row and meta value that changes, in memory — which is exactly what `--dry-run` runs; `apply()` writes that plan through SQLite's backup API into a private tmp, rewrites, checkpoints, fsyncs, renames over the run id's own path and unlinks the old sidecars) and one command module (`src/sensorium/query/redact_cmd.py`: the two forms, the per-trace lines, the summary, the exits, the stale-key sweep, `--all`'s directory mode). The rule itself is not re-implemented anywhere: `redact.env`'s name rule, `redact_values.{named,named_return,value,exc,text,count}` and `redact.meta(…, by="retrofit")` are called as the recorders call them, under a `redact_values.install(key, knobs)` scoped to the plan. The stale `redaction.key.<pid>.tmp` sweep (A's R15 hazard) lands in `redact_key.sweep_stale`. E16 part C is its own instrument on part A's machinery.

**Tech Stack:** Python 3.13 (`src/sensorium/`), pytest, sqlite3's `Connection.backup`; the corpus runner (`corpus/run_corpus.py`); the acceptance instrument pattern (`tests/acceptance_e16/e16a.py`'s `_run`, `_grep_counts`, `_stat_tree`, `_sha8`, `assemble_e16a`'s `Refused`, `write_into`, `scrub`, `offenders`). No Rust, no Node: the runtimes, converters and transform are untouched.

**Spec:** `docs/superpowers/specs/2026-09-13-sensorium-secrets-redaction-design.md` — §7 is the command, §4.3 the stamp, §4.4 the hash, §5.5 the modes, §9 H4 the gate, §11 what is out, and **§13's `### 2026-09-15 — PR C designed` section holds decisions C1–C20 and the store's measured state**, which this plan argues from. Section numbers below (§n) are the spec's; `Cn` are that section's decisions; `Pn` are this plan's own (the table below).

## Decisions this plan makes (each amends the spec non-silently; Task 9 appends them to §13)

| # | decision | why |
|---|---|---|
| P1 | **`plan()` is the whole judgement and `--dry-run` is `plan()` alone.** `Plan` carries every changed row keyed by id (`payloads: dict[int, str]`, `unwinds: dict[int, str]`, `outputs: dict[int, str]`), the meta values that change (`meta: dict`), the counts, the refusal or the skip, and the original's mode. `apply()` reads a `Plan` and touches nothing the plan did not name. | C14; one judgement, one writer; a dry run that ran a different code path would be a different claim |
| P2 | **The stamp's `values` is ADDITIVE:** the previous stamp's `values` (0 when absent) plus what this run redacted. On a pre-rule trace that is this run's count; on a 0.16.0 trace it is the recorder's count plus the retrofit's. C6's "what the trace HOLDS" cannot be recounted for output rows and messages (a content hit leaves text, not a marker), so the honest number is the sum of the hands' counts. | C6 amended: additive, not recounted |
| P3 | **The stale-key sweep runs under `--dry-run` too**, and the directory-mode clause prints in both modes. A dead process's leftover is not a trace, and §7's "change nothing" is about traces; keeping the sweep out of the dry run would make the two stdouts differ exactly when a reader is comparing them. C10's byte-identity therefore holds unconditionally. | C10, C13 |
| P4 | **A value already equal to the marker is never digested.** An env value that is literally `<redacted>` but whose name is not in the table (a hand-edited trace, a converter from elsewhere) is left as it is and gains no digest; `redact_values.named` already returns a capture carrying `redacted` untouched. | a digest of the marker is a wrong digest (§5.4's reason) |
| P5 | **The stamp is rewritten only when something else changed OR the trace was not already at `mode: "on"`.** A trace already `on` whose pass found nothing prints `nothing to redact` and is not rewritten, even if the caller's knobs differ from the recorded ones; a pre-rule or `mode: "off"` trace is stamped `on` even when nothing fired (§7: "redacted and stamped"). | §7's two sentences read together |
| P6 | **A `mode: "on"` trace that is UNKEYED (`keyed: false`) under a keyed store proceeds:** its null digests stay null, new digests are the store's, and the stamp becomes `keyed: true` with the store's `key_id`. A name with a null digest under a keyed stamp reads as unverifiable in `refocus` (`redact._unkeyed`), which is what it is. Only a keyed trace under ANOTHER key is refused (C5). | the fallback loses comparability and never safety (§3) |
| P7 | **The RETURN name rule reads `code_objects.qualname` for the event's `code_id`;** a RETURN with no `code_id` (none is written today) takes `value()` only. `last_segment` is `redact_values`' own. | B7's rule, from the table the trace holds |
| P8 | **Events are walked in id order in one pass, unchanged rows are never written,** and equality is on the parsed object (`new != obj`), not the text — a recorder's own `default=repr` fallback could have produced text `json.loads` round-trips differently, and a row that decodes to the same object has nothing to rewrite. | byte-identical where nothing was redacted |
| P9 | **The corpus case records under `env: {SENSORIUM_NO_REDACT: "1", …}`** (the runner merges a case's `env:` last into the RECORDING's environment and not into the questions' — `_cli(cmd, wd, sdir)` at `run_corpus.py:535`), so the trace holds plaintext with a two-key `mode: "off"` stamp and the questions run the retrofit under the harness's own environment. `env N redacted (…)` cannot pin `N` (the launching shell's `SSH_AUTH_SOCK` fires or does not), so the case pins the line with `expect_line` groups that name the token variable and the value count. | the harness's shape; a count of somebody's shell is not a test |
| P10 | **E16 part C reads the token's VALUE from the copy's own traces** (`meta.env["CLAUDE_CODE_MESSAGING_TOKEN"]` of the first `*.db`, through a read-only sqlite connection), never from the environment and never printed — the record cites `sha256` first 8 hex. There is no mint: H4 is about a secret that is already there. | §9's H4 names the variable, not a probe |
| P11 | **The part C rehearsal (`E16_DRY=1`) runs on a FABRICATED store** — three Python-shaped synthetic traces (`store/writer.TraceWriter`) carrying a `dry-` decoy under `CLAUDE_CODE_MESSAGING_TOKEN` and in one `str` RETURN, one output row and one `children` element, at 0644 with sidecars, plus a `redaction.key` from `Key.load_or_create` — and never copies the live store. The rehearsal checks every phase runs and every artifact path the assembler reads exists. | A's lesson: the dry run is for the plumbing; the live store is copied once, for the measurement |
| P12 | **The measurement's copy is `cp -a` of `~/.sensorium/traces` and `redaction.key`** into `$E16C_DIR/store-c/` (nothing is writing to the live store during the copy; the instrument refuses if any `.<run>.db.tmp` or `incomplete: true` trace is in the copy — H4 is about completed traces). The `-wal`/`-shm` sidecars are copied with their databases: the retrofit's backup carries their pages, and `grep-after` sweeps whatever files remain. | C7; the copy must be the database, sidecars included |
| P13 | **H4's four clauses are four rows of one cell:** (1) every `*.db` in the copy has a dry-run line naming `CLAUDE_CODE_MESSAGING_TOKEN` among its env names; (2) after the real run, `grep -rc -F <value>` over every file under `store-c/` is 0 (the `-wal`/`-shm` gone or 0, the key 0); (3) `info <run>` exits 0 for every trace and its `redaction:` line says `by retrofit`; (4) the dry run's stdout equals the real run's, byte for byte. PASS iff all four; STOP names the first failing row and what it read. `273` is §9's expectation and is REPORTED beside the copy's count, never gated. | §9's H4 row, read as an instrument reads it |
| P14 | **The live retrofit is a post-merge chore, not a task** (C18): after the merge and the global tool's reinstall at 0.17.0, `sensorium redact --all --dry-run` then `sensorium redact --all` on `~/.sensorium`, transcripts kept under `$E16C_DIR/live-transcripts/`, the outcome recorded in memory and the next CARRIED-DEBT entry — conditional on §4 reading H4 PASS. | destructive actions are Brice's; the condition is the record |

### Task 2: `redact_store.plan` — the judgement

**Files:** Create `src/sensorium/redact_store.py`, `tests/test_redact_store_plan.py`.

**Interfaces (produces):**
```python
# src/sensorium/redact_store.py
from sensorium import redact, redact_values as rv
from sensorium.redact_key import Key
from sensorium.store import db
from sensorium.ts.invocation import env_hash as _kv_env_hash

TMP_SUFFIX = ".redact"                       # the tmp is f".{run}.db{TMP_SUFFIX}.{pid}.tmp" beside the trace
KV_LANGS = frozenset({"rust", "typescript"})

@dataclass(frozen=True)
class Plan:
    path: Path; run: str; lang: str
    refused: str | None = None               # C9's sentence, no "REFUSED:" prefix, no path
    skipped: str | None = None               # "in flight (incomplete)"
    env_names: tuple[str, ...] = ()          # env names THIS run redacted, sorted
    values: int = 0                          # what THIS run redacted (captures, output rows, messages, children elements)
    meta: dict = field(default_factory=dict) # meta keys to (re)write: subset of env, env_hash, redaction, children
    payloads: dict[int, str] = field(default_factory=dict)   # events.id -> json
    unwinds: dict[int, str] = field(default_factory=dict)    # frames.id -> json
    outputs: dict[int, str] = field(default_factory=dict)    # output.id -> text
    mode_before: int = 0o600                 # st_mode & 0o777 of the original
    @property
    def rewrites(self) -> bool: ...          # bool(meta or payloads or unwinds or outputs)
    @property
    def tightens(self) -> bool: ...          # mode_before != 0o600
    @property
```
