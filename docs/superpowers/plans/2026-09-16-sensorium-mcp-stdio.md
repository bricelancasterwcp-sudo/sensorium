# sensorium as an MCP server — the local stdio slice (E17): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sensorium mcp` — a dependency-free JSON-RPC 2.0 server on stdio that exposes the nine query commands as MCP tools (plus `record` and `refocus` under `--allow-run`), with schemas derived from the argparse parsers, every call a child process, results as the CLI's own text under an exit header, an output cap, an audit file, both MCP lifecycles (2026-07-28 `server/discover` and legacy `initialize`), the corpus asked through the wire, and E17 measured once.

**Architecture:** `src/sensorium/mcp/` in eight small modules: `schema.py` derives a tool's fields from its command's parser and rebuilds argv from a call's arguments (rejecting by name); `tools.py` holds the explicit tool tables, descriptions, annotations and the hand-written `record` schema; `child.py` runs `sys.executable -m sensorium <argv>` in its own session with a timeout and a SIGTERM→SIGKILL group kill; `result.py` builds the header, the stderr label, the head+tail cap and the structured content; `audit.py` writes `mcp.jsonl`; `jsonrpc.py` frames; `server.py` runs a reader thread (pings, cancels, queueing) and one worker (calls in order) and speaks both lifecycles; `cmd.py` is the `sensorium mcp` subcommand. `corpus/mcp_client.py` is a minimal stdlib client shared by the tests, the corpus's `--via mcp` mode and E17; `tests/test_mcp_conformance.py` drives the server with the official SDK as a dev-only oracle.

**Tech Stack:** Python 3.12–3.14 standard library only for the product (`argparse`, `json`, `subprocess`, `threading`, `queue`, `signal`, `os`); pytest; the corpus runner; the official `mcp` Python SDK **2.2.x** as the `conformance` dev extra (tests only); Claude Code 2.1.258 as the deploy-target smoke (H7).

**Spec:** `docs/superpowers/specs/2026-09-16-sensorium-mcp-stdio-design.md` — §2 the tool surface (D1–D10), §3 the protocol (D11–D15), §4 the process model (D16–D18), §5 the result (D19–D24), §6 policy and audit (D25–D30), §7 the command (D31), §8 the corpus (D32), §9 E17 pre-registered, §10 contract/tests/docs/versions (D33–D34), §11 out of scope, §12 risks. The decisions table below (P1–P30) amends the spec where the scouts and the plan's own adversarial review found it wrong; Task 11 appends them to §13.

## Decisions this plan makes (each amends the spec non-silently; Task 11 appends them to §13)

| # | decision | why |
|---|---|---|
| P1 | **The tool tables are explicit, and a test closes them over `cli._QUERY_MODULES`.** `tools.QUERY_MODULES` = the nine, `EXECUTE_MODULES = (refocus_cmd,)`, `NOT_TOOLS = (redact_cmd,)`; `test_every_query_module_is_placed` asserts `set(cli._QUERY_MODULES) == set(QUERY_MODULES) | set(EXECUTE_MODULES) | set(NOT_TOOLS)`. Field derivation stays automatic; a new *command* fails the suite until someone places it. | `_QUERY_MODULES` has eleven entries including `redact_cmd`; "derived from that list" (D31) would make `redact` a tool. A new command becoming a tool silently is the wrong default for an execution-capable surface. |
| P2 | **`action.required is True` → the field is in `required`; a required `_AppendAction` also gets `"minItems": 1`.** | `watch --at`, `watch --expr` and `refocus --focus` are required options; the spec's table only required positionals, so a model omitting them would get argparse's exit 2 for a field the schema called optional. |
| P3 | **The header words are `exit.MEANING`, a dict added to `exit.py`, holding the spec's D19 sentences verbatim:** `0: "the trace answered affirmatively"`, `1: "the trace answered negatively -- no match, no frame, no exception, none"`, `2: "the call is wrong -- fix the arguments and ask again"`, `3: "the trace cannot settle it -- change the recording and re-record"`. | D19 said "the exit module's own docstrings"; only exit 1's matched. One dict, one source, and the words are the ones `INSTRUCTIONS` teaches. |
| P4 | **`--- stderr ---` is emitted whenever stderr is non-empty**, stdout empty or not. | Two corpus refusals print only to stderr; the corpus client must attribute the body to a stream, and H1's stdout comparison needs the split to be lossless. Amends D20. |
| P5 | **D13 is tightened: under the per-request model both `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` are required; a request missing either is `-32602` naming the key.** A per-request request is recognised by the *presence of the protocolVersion key*, never by `_meta` being present (legacy requests carry `"_meta": {}`). | The falsifier fired at design time: the official client stamps both keys on every modern request. |
| P6 | **Every per-request-model result carries `resultType: "complete"` and `_meta: {"io.modelcontextprotocol/serverInfo": {"name": "sensorium", "version": <installed>}}` (the `{}` ping reply included); `server/discover` and `tools/list` additionally carry `ttlMs: 3600000` and `cacheScope: "private"`.** Legacy results carry none of these. | The official client hard-fails a modern `tools/call` without `resultType` and a modern `tools/list` without the cache fields; it reads `serverInfo` from `_meta`; 2026-07-28 asks for `serverInfo` on every result so a stateless client can identify the server. |
| P7 | **Under `--via mcp`, a question whose command word is not a tool is asked through the CLI path, never skipped**, and reported: `CaseResult.via_cli` lists the ids, the text summary appends `; N question(s) asked through the CLI (not tools)`, JSON gains `"via_cli": [...]` only when non-empty. | `redact_retrofit`'s two tool questions are only true AFTER its three `redact` questions rewrote the store; skipping the three strands the two. H1 reads `via_cli == the locked three`. |
| P8 | **The per-case server's environment is `_cli`'s** — `{**os.environ, "SENSORIUM_DIR": sdir, "PYTHONDONTWRITEBYTECODE": "1"}` — **never the case's `env:` block.** | Today a question's child never sees `case.env`; `info` prints `redaction: OFF (SENSORIUM_NO_REDACT)` from the live environment, so carrying `case.env` into the server would make MCP and CLI differ on `redact_retrofit`. H6 plants its token through the instrument's own server, not the corpus runner. |
| P9 | **`--store DIR` sets `os.environ["SENSORIUM_DIR"] = str(Path(DIR).resolve())` in the server process at start.** Children inherit it; `audit.path()` and the server's own exit line in `invocations.jsonl` land in that store. | One mechanism, and `paths.trace_root()` reads the variable on every call. |
| P10 | **The `record` header reads `exit N: the recorded command's own status (2 and no trace when recording was refused)`; a signal-killed child reads `exit -S: killed by <signal name>`.** | `run`'s exit is not the four-way contract, and a negative returncode is what `Popen` reports for a signal. |
| P11 | **The kill is `kill_group(proc)`: `killpg(pgid, SIGTERM)` → poll the GROUP (`killpg(pgid, 0)`) and the leader (`proc.poll()`) every 0.05 s for up to 2.0 s → ALWAYS `killpg(pgid, SIGKILL)` (`ProcessLookupError` suppressed at every step) → `proc.communicate(timeout=2.0)`, and on that expiry close the pipes and return what was read.** EOF on stdin and SIGTERM to the server both end in `serve()`'s `finally`, which runs that kill on the in-flight child, drops the queue and joins the worker; the SIGTERM handler itself only sets `SIG_IGN`, sets `closing` and raises `SystemExit(0)`. | The SDK closes stdin, waits 2 s, SIGTERMs the server (its own session only), waits 2 s, SIGKILLs: a handler that unwound an EOF kill mid-grace would orphan the child; a leader that dies on SIGTERM while a grandchild ignores it would otherwise hold the pipes and wedge the worker forever (H5 reads the group, not the leader). |

class Child:
    def __init__(self, argv: list[str], cwd: str | None, python: str | None, env: dict, timeout: float, log=None)
        # log: callable(str); run() calls it exactly once at spawn with f"child {pid} pgid {pgid} tool {tool}" (tool = the server's tool name, passed as `name`; the server passes its own log()) — the ONE format every reader parses

def cap(text, limit, narrowing):
    nl = text.find("\n")
    head_line, body = (text, "") if nl < 0 else (text[:nl], text[nl + 1:])
    raw = body.encode("utf-8")
    if len(raw) <= limit:
        return text, False, 0, 0
    keep_tail = min(4096, limit // 4)
    keep_head = limit - keep_tail
    head = raw[:keep_head]; head = head[:head.rfind(b"\n") + 1] if b"\n" in head else head
    tail = raw[-keep_tail:]; tail = tail[tail.find(b"\n") + 1:] if b"\n" in tail else tail
    omitted = raw[len(head):len(raw) - len(tail)]
    lines = omitted.count(b"\n")
    narrow = ", ".join(narrowing) if narrowing else "nothing on this tool"
    marker = f"[... {lines:,} lines ({len(omitted):,} bytes) omitted; narrow with: {narrow} ...]\n"
    out = head.decode("utf-8", "replace") + marker + tail.decode("utf-8", "replace")
    return head_line + "\n" + out, True, lines, len(omitted)

**The server's rules** (spec §3, §4 + P5/P6/P20/P21/P27):
- **Threads.** The calling thread reads stdin line by line. `ping` is answered inline (`{}`; under the per-request model `{"resultType": "complete", "_meta": {serverInfo}}`); `notifications/cancelled` is handled inline; every other request goes onto a `collections.deque` guarded by ONE `threading.Condition`; one daemon worker pops in order and answers. **The pop and the publish of `self._inflight = (id, child)` happen together under that Condition, the reader reads `_inflight` under it, and the worker clears it under it before writing the response** — so a cancel can never fall between the pop and the publish. The worker owns `Session`; the reader never touches it. **The worker wraps every request in `try/except Exception`:** the error is logged (`internal error on <method> id <id>: <type>: <msg>`) and answered `-32603 Internal error` with `data: {"type": <class name>}`; the worker never dies. A `BrokenPipeError`/closed-file error on write is the `Writer`'s `closing`, never an exception out of the worker; a `UnicodeDecodeError` cannot reach the reader because `main()` reconfigured stdin with `errors="replace"` (a replaced byte makes a line that is not JSON → `-32700` like any other).
- **Era.** A request whose `params["_meta"]` carries `META_VERSION` is per-request-model: version not in `SUPPORTED` → `-32022 Unsupported protocol version` with `data: {"supported": list(SUPPORTED), "requested": v}` — **`server/discover` included** (Task 7 (g)/(j) rely on it); `META_CAPS` absent → `-32602 missing _meta key io.modelcontextprotocol/clientCapabilities` (P5). A request with no `META_VERSION` key is legacy: `session.legacy_version` must be set, else `-32602 not initialized: send initialize or server/discover first, or carry _meta protocolVersion`. The only exemptions from the era check are `initialize` (its own rule below) and `ping` (always answered).
- **`server/discover`** (per-request model only; a discover with no `_meta`, or `_meta` without the version key, is `-32602 server/discover needs _meta protocolVersion`; one with an unsupported version is `-32022` per the era rule): result `{"resultType": "complete", "supportedVersions": list(SUPPORTED), "capabilities": {"tools": {}}, "instructions": INSTRUCTIONS, "ttlMs": TTL_MS, "cacheScope": CACHE_SCOPE, "_meta": {META_SERVER: {"name": "sensorium", "version": version()}}}`; sets `session.discovered = True`.
- **`initialize`** (**P27:** the offered version is echoed iff it is in `LEGACY`; anything else — unknown, or `2026-07-28`, which has no `initialize` — is answered `LEGACY_LATEST`): result `{"protocolVersion": v, "capabilities": {"tools": {}}, "serverInfo": {"name": "sensorium", "version": version()}, "instructions": INSTRUCTIONS}`; sets `session.legacy_version = v`. `notifications/initialized` is ignored.
- **`structured`** for a result = per-request model, or `legacy_version in ("2025-06-18", "2025-11-25")`; `modern` = per-request model. Every modern result the server writes gains `"resultType": "complete"` and `"_meta": {META_SERVER: {...}}` (P6) at the writer call site — one helper, `self._modern(result)`. `tools/list` → `{"tools": [tools.to_wire(t, structured) …]}` plus, when modern, `ttlMs`, `cacheScope`; `cursor` ignored.
- **`tools/call`**: `arguments = params.get("arguments") or {}`; `params["name"]` absent or not a string, or `arguments` present and not an object → `-32602 tools/call needs a string name and an object arguments` (no audit line: no tool was named). `name` not in the table → `-32602 Unknown tool: <name>` + `audit.record_rejection(name, -32602, "unknown_tool", msg)`. `tools.command_argv` raising `Rejection` → **`writer.result(id, result.rejection_result(r, structured, modern))`** (P30: an `isError` result, exit 2) + the audit rejection line with its reason and fields. Else `Child(argv, cwd=extras["cwd"], python=extras["python"], env=dict(os.environ), timeout=run_timeout if tool.executes else timeout, log=self.log).run()` (published as `_inflight` under the Condition as above); then `result.call_result(tool, outcome, options.max_output, structured, modern)` → `writer.result(id, …)` + `audit.record_call(...)`; a cancelled outcome → NO response, `audit.record_cancel(tool, arguments, queued=False, ms)`.
- **`notifications/cancelled`**: `requestId` equal (`==` on the JSON value) to the in-flight id → `child.cancel()` (on the reader thread; the worker's `communicate` returns and reads the flag); equal to a queued id → removed from the deque, `audit.record_cancel(..., queued=True, ms=None)`; else ignored. **Every other notification** ignored. **Every other request** → `-32601 Method not found: <method>`.
- **Errors from `parse_line`** are written as given (id `None` when unknown). Nothing but JSON-RPC ever reaches stdout; `log()` is the only stderr writer.
- **Shutdown — one path.** `serve()` runs the reader loop inside `try/finally`. The `finally` — reached by EOF, `SystemExit`, `KeyboardInterrupt`, `BrokenPipeError` or any bug — first sets SIGTERM to `SIG_IGN` (a second SIGTERM must never unwind the kill), sets `closing`, runs the full `kill_group` on the in-flight child (P11), drops the queue, appends the worker's sentinel and `join(5.0)`s the worker so no daemon thread is mid-write at interpreter finalisation. **The SIGTERM handler does three things only:** `signal.signal(SIGTERM, SIG_IGN)`, set `closing`, `raise SystemExit(0)` — it never calls `Child.cancel()` itself (a handler that ran the kill would abort an EOF kill already in its grace wait). `main()` maps `SystemExit(0)`, EOF and `BrokenPipeError` to exit 0 and logs which.
- **Boot and event logging** (stderr, one format each): `serving <n> tools (allow_run=<bool>) store=<paths.trace_root()>`; when `audit.disabled()`: `audit off (SENSORIUM_NO_INVOCATION_LOG)`; per handshake (worker thread): `handshake discover <version>` or `handshake initialize <offered> -> <answered>`; per spawn (from `Child.run` through `log`): `child <pid> pgid <pgid> tool <name>` — the one format, emitted nowhere else.
