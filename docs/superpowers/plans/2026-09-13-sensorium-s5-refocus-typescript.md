# S5, the refocus slice — `refocus` for TypeScript traces, and E15: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sensorium refocus <run> --focus <spec>` answers on a TypeScript trace — re-runs the whole recorded harness invocation one flag deeper, finds the pair in the store by test file, compares it under the shared comparator, and prints a licence a TypeScript pair can earn — measured once on the lens as E15, with the scheduled `js_inspect._MORE` removal folded in.

**Architecture:** The driver (`sensorium ts run`) learns `--refocus-of <run>` and writes it into `invocation.json`; the converter lifts it and the driver's working directory (`harness_cwd`) into every member's meta and declares `capabilities.refocus: true`. A new Python module `refocus_typescript.py` owns the one thing a TypeScript recording does differently — it cannot be re-run in this process, and one invocation is many traces — and calls back into `refocus_cmd`/`refocus_report`/`diff_cmd` for everything else. The shared licence code learns that threads can be unverifiable, gains a harness set beside the session set, and lends the Rust branch's two helpers to a second language as pure moves.

**Tech Stack:** Python 3.13 (`src/sensorium/`), pytest; Node ≥ 24 ESM `.mjs` under `typescript/` (UNCHANGED this slice); vitest 4.1.9 in `corpus/typescript/` and on the lens; the corpus runner (`corpus/run_corpus.py`); the acceptance-instrument pattern of `rust/tests/acceptance_e4*.py` and `typescript/acceptance/e12p*.py`.

**Spec:** `docs/superpowers/specs/2026-09-13-sensorium-s5-refocus-typescript-design.md` (PR #37, branch `docs/s5-refocus-ts-design`). The spec is the authority; this plan is its argument. Section numbers below (§n) are the spec's unless prefixed by a file name.
